## 1. 개요
- 목표: 주행 영상에서 Hough Transform 기반으로 차선을 실시간 검출하고, 차선 이탈 시 경고를 표시
- 개발 환경: C++17, OpenCV 4.x, (OS / CPU 기입)
- 사용 영상: (출처, 해상도, FPS, 길이 기입)

## 2. 역할 분담
| 이름 | 역할 | 구현 |
|---|---|---|
| 이현진 (A) | 전처리, ROI 설정, 파라미터 튜닝 | `PreprocessPipeline`, `RoiMasker`, `detectEdges`, ROI 프리셋, 튜닝 UI |
| 황유림 (B) | 허프 변환, 좌우 대표 차선, 오프셋, 차선 변경 감지 | `detectLines`, `estimateLaneLines`, `computeLanePosition`, `updateLaneChangeDetector` |
| 김선형 (C) | 통합, 안정화, 실시간 측정, 시각화, 데모 영상, 보고서 | `LaneTracker`, `drawLaneOverlay`, `drawHud`, `main` |
| 황유림 · 김선형 | 차선 이탈 경고 | `DepartureWarning` |

## 3. 전체 알고리즘 흐름
```
입력 프레임 (960×540으로 축소)
  → [Gray] → [GaussianBlur 5×5] → [Canny 30/90] ─┐
  → [(B−R)×4] → [GaussianBlur] → [Canny 30/90] ──┴→ [OR] → [ROI 사다리꼴 마스크]
  → [HoughLinesP] → [기울기·위치로 좌/우 분류] → [선분 묶음 선택 → 길이 가중 평균 → 대표 차선]
  → [프레임 간 안정화(EMA, 반대편 추정)] → [차량 중심 자동 보정] → [오프셋 계산] → [차선 이탈 판정]
  → [시각화: 차선 · 주행 영역 · 오프셋 · FPS · 경고]
```
(그림: 단계별 중간 결과 이미지 — 원본 / Canny / ROI / Hough 선분 / 최종 결과. `--debug` 화면 캡처 사용)

## 4. 단계별 구현
### 4.1 전처리 (A)
- 처리 해상도 960×540: 1080p 대비 픽셀 수 1/4, 전처리 약 2 ms/frame
- 흑백 변환: 연산량 감소, 차선은 밝기 대비로 충분히 구분됨
- Gaussian Blur 5×5: 커널 없음/3/5/7/9 비교 → 3→5에서 잡음 엣지가 크게 줄고 7 이상은 먼 차선이 사라짐
- Canny 30/90 (1:3): 50/150은 어두운 영상에서 차선을 놓치고, 20/60은 가드레일·차량 엣지 과다
- ROI는 Canny 뒤에 적용: 블러 영상에 먼저 씌우면 ROI 경계가 강한 엣지로 잡힘
- ROI 프리셋: 카메라 높이가 영상마다 달라 highway / city 두 가지 (화면 비율 기반)
  (README의 비교 표 첨부)
- **파란 차선(버스전용차로) 엣지 (C)**: 흑백으로는 차선 88 / 노면 86으로 구분 불가 → (B − R)×4 영상에서 엣지를 따로 구해 OR.
  낮 기준 차선 B−R +18~25, 노면 −32 / 해질녘 차선 +26~32, 노면 0~3 (실제 영상 픽셀 측정)
  (캡처: `--no-blue` 전 / 후 비교)

### 4.2 허프 변환과 대표 차선 (B)
- `HoughLinesP(rho=1, theta=π/180, threshold=30, minLineLength=30, maxLineGap=20)`
- 기울기 필터: |slope| < 0.3 (수평선: 정지선·그림자·앞차) 또는 > 3.0 (거의 수직: 차량 옆면 등) 제거
- 좌/우 분류: 영상 좌표계(y 아래로 증가)에서 왼쪽 차선은 slope < 0, 오른쪽은 slope > 0.
  추가로 선분 중점이 화면 왼쪽/오른쪽 절반에 있는지 확인해 반대편 노이즈 제거
- 위쪽 끝(ROI 상단 x)이 화면 중앙을 넘어 반대편으로 가는 선 제거 (보닛 테두리, 가로지르는 그림자)
- 대표 차선 (B·C): 같은 쪽 선분을 ROI 하단 x 기준으로 묶고(간격 3%), 이전 프레임 차선 근처(8%)에서
  선분 길이 합이 가장 큰 묶음을 길이 가중 평균 → 노면 이음매·갓길 경계 등 옆의 선에 끌려가지 않음
- 좌우 차선이 ROI 안에서 교차하면 그 프레임 결과 폐기
- 대표 차선을 ROI 상단·하단 y에서의 x 좌표로 표현해 이후 단계에서 사용

### 4.3 프레임 간 안정화 (C)
- 문제: 허프 결과가 프레임마다 흔들리고 가끔 한쪽 차선을 놓쳐 선이 깜빡임
- 좌우 차선 각각의 상단·하단 x에 지수이동평균 적용: `x_t = α·x_측정 + (1-α)·x_{t-1}`, α = 0.25
- 미검출 프레임은 최대 15프레임까지 직전 값 유지, 오래 놓쳤다 다시 잡으면 바로 새 값 사용
- 한쪽만 보이면 학습해 둔 차선 폭으로 반대편 추정 → 차가 치우쳐 반대편 차선이 ROI 밖으로 나가도 이탈 판단 가능
- (캡처: 안정화 전/후 비교)

### 4.4 오프셋 계산과 차량 중심 보정 (B · C)
- 차선 중앙 = (좌측 차선 하단 x + 우측 차선 하단 x) / 2, 차선 폭 = 우측 − 좌측
- 차량 위치: 블랙박스가 차량 중앙에 있지 않아(테스트 영상은 화면 가로의 약 0.44) 화면 중앙을 쓰면 직진 중에도 오프셋 발생
  → 처음 60프레임(약 2초) 차선 중앙 평균을 차량 위치로 자동 보정 (`--car-x`로 고정 가능)
- 차선 폭 대비 오프셋 = (차선 중앙 − 차량 위치) / 차선 폭 → 해상도·ROI·차선 폭과 무관
- 차선 폭이 ROI 너비의 30~150%를 벗어나면 오검출로 보고 판단 보류

### 4.5 차선 이탈 경고 (B · C)
- |오프셋 / 차선 폭| > 20%가 8프레임(약 0.27초) 연속 → 경고 ON
  - 근거: 승용차 폭 ~1.8m, 차선 폭 ~3.5m → 차량 중심이 20% 정도 벗어나면 바퀴가 차선에 접근
  - 오프셋 +: 차선 중앙이 오른쪽 = 차량이 왼쪽으로 치우침 → `LANE DEPARTURE! <<< LEFT`
  - 오프셋 −: `LANE DEPARTURE! RIGHT >>>`
- 경고 중 14% 미만 → 경고 OFF (히스테리시스로 경계 근처 깜빡임 방지)
- 차선이 없거나 보정 중(처음 2초)이면 판단 보류
- 경고 시 주행 영역을 빨간색으로 바꾸고 화면 상단에 배너 표시
- 개선 과정: 처음에는 ROI 중앙 기준 오프셋 10%, 3프레임으로 판정 → 실제 영상에서 직진 중에도 경고가 남
  (원인: 카메라 장착 위치 치우침, 파란 차선 미검출로 갓길 경계를 차선으로 잡음) → 위 방식으로 수정
- 차선 변경 감지(B, 실험): 중앙에 10프레임 머문 뒤 8% 이상 벗어난 상태가 8프레임 이어지면 "LANE CHANGE DETECTED"

### 4.6 통합 및 시각화 (C)
- 결과 화면: 좌측 차선(빨강) / 우측 차선(파랑), 주행 영역 반투명 채움, 차선 중앙(흰 점) / 차량 위치(노란 점), 오프셋, FPS, 경고 배너
- 디버그 화면(`d` 키 또는 `--debug`): 결과 + ROI 외곽선 / ROI 엣지 + 허프 선분
- 원본 프레임은 그대로 두고 복사본에 그림 → 그린 선이 다음 처리에 섞이지 않음
- `--out=demo.mp4`로 결과 화면을 그대로 녹화해 데모 영상 제작
