# Lane Detection (C++ / OpenCV)

도로 주행 영상에서 차선을 검출하고 차선 중심의 위치 변화를 분석하는 프로젝트이다. 딥러닝 모델을 사용하지 않고 OpenCV 기반의 전통적인 영상처리 기법을 이용한다.

현재 영상 전처리 파이프라인과 허프 변환 기반의 차선 검출 기능을 구현했다. 흑백 엣지에 더해 파란 차선(버스전용차로) 엣지를 따로 구해 합치고, 좌우 대표 차선과 차선 사이의 주행 영역을 표시한다. 차량(카메라) 중심은 처음 2초 동안 자동 보정하고, 프레임 간 안정화(EMA)로 차선 깜빡임을 줄였다. 차선 폭 대비 오프셋이 기준을 넘으면 **차선 이탈 경고**(`LANE DEPARTURE!`, 방향 포함)를 표시한다. 차선 변경 감지는 실험 단계로 함께 남겨 두었다.

```text
영상 입력
   ↓
[영상 전처리]
Gray → Blur → Top-hat ×2 ─────────┐
(B − R) → Blur → Top-hat ×4 ──────┼→ max = 차선 특징 영상 → Canny → ROI 마스크
(min(R,G) − B) → Blur → Top-hat ×3 ┘   (밝은 띠 / 파란 차선 / 노란 차선만 남김)
   ↓
[차선 후보 검출]
HoughLinesP → 기울기·위치 기반 좌우 분류 (위쪽 끝이 반대편으로 넘어가는 선 제거)
   ↓
[대표 차선 추정]
하단 x가 가까운 선분끼리 묶음 → 이전 차선 근처에서 가장 긴 묶음 선택 → 길이 가중 평균
   ↓
[프레임 간 안정화]
EMA 평활화 + 짧은 미검출 유지 + 한쪽만 보이면 차선 폭으로 반대편 추정
   ↓
[차량 중심 보정 · 오프셋 · 차선 이탈 경고]
처음 2초 차선 중앙 평균 = 차량 위치 → |오프셋 / 차선 폭| > 20% 가 8프레임 연속 → 경고, 14% 미만 → 해제
   ↓
[결과 표시]
대표 차선 / 주행 영역(이탈 시 빨강) / 오프셋 / FPS / 경고 배너
```

## 파일 구조

모든 코드는 `lane_detection.cpp` 한 파일에 있고, 번호 붙은 섹션 주석(`// 1. 설정` 등)으로 구분한다. `std`와 `cv`는 `using namespace`로 접두사를 생략했고, 알고리즘 코드는 `namespace lane` 안에 있다.

| 섹션 | 내용 |
|---|---|
| 1. 설정 | `BlurParams`, `CannyParams`, `RoiParams`, `PipelineConfig`, ROI 프리셋(`applyRoiPreset`) |
| 2. 영상 입출력 | `VideoSource`(읽기 및 처리 해상도로 축소), `VideoSink`(저장) |
| 3. ROI | `makeRoiPolygon`, `RoiMasker`(마스크 캐싱) |
| 4. Canny | `detectEdges`, `computeAdaptiveThresholds` |
| 5. 전처리 파이프라인 | `PreprocessPipeline`, `PreprocessResult` |
| 6. 차선 검출·경고 | `detectLines`(허프 변환), `estimateLaneLines`(좌우 대표 차선 계산), `LaneTracker`(프레임 간 안정화), `computeLanePosition`(차선 중심·오프셋), `DepartureWarning`(차선 이탈 경고), `updateLaneChangeDetector`(차선 변경 감지, 실험), `drawLaneOverlay`·`drawHud`(시각화) |
| 7. main | 프레임 루프, 처리 시간 측정, 결과/디버그 화면 전환, 데모 영상 저장, 튜닝 UI |

파일 하나를 여러 명이 고치면 git 충돌이 나기 쉬우니, 각자 자기 섹션만 수정하고 푸시 전에 `pull`로 합치는 것이 좋다.

## 다음 단계 담당자를 위한 인터페이스

`PreprocessPipeline::process(frame)`이 돌려주는 `PreprocessResult` 중 허프 변환 입력은 **`roiEdges`** 하나다.

- `roiEdges` : `CV_8UC1`, 엣지=255, ROI 밖=0. `cv::HoughLinesP`에 그대로 넣으면 된다.
- 좌표계는 `main`의 `frame`(처리 해상도로 축소된 프레임, 기본 960×540)과 동일하다. 검출한 직선은 이 프레임 위에 바로 그리면 된다.
- `roiPolygon` : ROI 꼭짓점(좌하, 좌상, 우상, 우하). 소실점/차선 폭 계산에 쓸 수 있다.
- 이탈 경고 단계는 `frame.size()`의 중앙 x를 차량 위치로 보면 된다 (카메라가 차량 중앙에 장착되었다는 가정).

새 단계는 6번 섹션(`}  // namespace lane` 앞)에 `namespace lane` 안의 함수로 추가하고, `main()` 루프의 처리 순서(1) 전처리 → 2) 허프·대표 차선 → 3) 안정화·오프셋·이탈 경고 → 4) 시각화) 중 알맞은 위치에서 호출한다. 전처리 코드는 수정할 필요가 없다.
### 3. 좌우 대표 차선 계산

허프 변환으로 검출된 선분을 기울기와 중점의 X 좌표를 기준으로 좌우 차선 후보로 분류한다.

- |기울기| < 0.45(가드레일·정지선·그림자 등 수평에 가까운 선) 또는 > 3.0(차량 옆면 등 수직에 가까운 선)은 버린다. 테스트 영상의 실제 차선은 |기울기| 0.6~1.2이고, 가드레일 아래 띠가 0.32 정도라 0.3 기준으로는 차선으로 잡혔다.
- 좌측 차선: 음의 기울기, 화면 중앙보다 왼쪽에 위치
- 우측 차선: 양의 기울기, 화면 중앙보다 오른쪽에 위치
- 선분 위쪽 끝(ROI 상단에서의 x)이 화면 중앙을 크게(8%) 넘어 반대편으로 가는 선은 버린다. 차선은 위로 갈수록 소실점으로 모이므로, 이런 선은 보닛 테두리나 가로지르는 그림자다.
- 같은 쪽 선분을 ROI 하단 x 기준으로 묶는다(간격 3% 이내). 한 차선의 양쪽 엣지와 점선 조각이 한 묶음이 된다.
- 이전 프레임 차선 근처(8% 이내) 묶음 중 선분 길이 합이 가장 큰 묶음을 고르고, 그 안에서 길이 가중 평균으로 대표 기울기와 절편을 계산한다. 전체를 평균하면 노면 이음매·갓길 경계 같은 옆의 선에 대표 차선이 끌려간다.
- 좌우 차선이 ROI 안에서 교차하면 그 프레임 결과는 버린다.
- 두 대표 차선을 ROI 상단과 하단에 맞춰 표시한다.

대표 차선은 좌측 빨간색, 우측 파란색으로 표시한다.

### 4. 주행 영역 및 오프셋 계산

좌우 대표 차선 사이를 반투명 초록색으로 채워 주행 영역을 시각적으로 표시한다.

차선 중심은 ROI 하단에서 좌우 대표 차선의 X 좌표를 평균해 계산한다.

```text
차선 중심 = (좌측 차선 하단 X + 우측 차선 하단 X) / 2
차선 폭   =  우측 차선 하단 X − 좌측 차선 하단 X
오프셋(px) = 차선 중심 − 차량 위치
차선 폭 대비 오프셋 = 오프셋 / 차선 폭      (이탈 경고에 사용. ±50%면 차량 중심이 차선 위)
오프셋 비율 = 오프셋 / ROI 너비             (차선 변경 감지에 사용)
```

오프셋이 양수이면 차선 중심이 차량보다 오른쪽, 즉 차량이 왼쪽으로 치우친 것이다. 차선 폭이 ROI 너비의 30~150%를 벗어나면 잘못 잡은 것으로 보고 판단하지 않는다.

**차량 위치 자동 보정 (`CarCenterCalibrator`):** 블랙박스는 차량 정중앙에 달려 있지 않은 경우가 많다(테스트 영상은 차선 중앙이 화면 가로의 약 0.44). 화면 중앙이나 ROI 중앙을 차량 위치로 쓰면 똑바로 달려도 오프셋이 생겨 오경보가 난다. 그래서 처음 60프레임(약 2초) 동안 검출된 차선 중앙의 평균을 차량 위치로 쓴다(처음에는 정상 주행 중이라고 가정). 보정 중에는 이탈 경고를 하지 않는다. 종료 시 보정값이 출력되며, `--car-x=0.44`처럼 고정할 수도 있다.

### 5. 프레임 간 안정화 (`LaneTracker`)

허프 결과는 프레임마다 조금씩 흔들리고, 가끔 한쪽 차선을 놓친다. 그대로 그리면 선이 떨리거나 깜빡이므로 좌우 차선 각각을 따로 추적한다.

```text
x_t = α · x_측정 + (1 − α) · x_{t−1}      (α = 0.25, ROI 상단·하단 x 각각)
```

- 차선을 못 찾은 프레임은 최대 15프레임까지 직전 값을 유지하고, 그 이상이면 해당 차선을 버린다.
- 양쪽이 다 보일 때 차선 폭(상단·하단)을 학습해 두고, 한쪽만 보이면 `보이는 쪽 ± 차선 폭`으로 반대편을 추정한다(화면에는 얇은 선). 차가 한쪽으로 치우치면 반대편 차선이 ROI 밖으로 나가는데, 이때가 바로 이탈 상황이라 판단을 멈추면 안 된다.
- 오래 놓쳤다가 다시 잡히면 평균 없이 바로 새 값을 쓴다 (예전 위치에 끌려가지 않게).
- α를 키우면 반응이 빨라지고, 줄이면 더 안정적이다.

### 6. 차선 이탈 경고 (`DepartureWarning`)

4번의 **차선 폭 대비 오프셋**으로 판단한다. 해상도·ROI 크기·차선 폭과 무관한 값이다.

| 조건 | 동작 |
|---|---|
| \|오프셋 / 차선 폭\| > 20% 가 8프레임(약 0.27초) 연속 | 경고 ON. 오프셋 + → 차량이 왼쪽으로 치우침(`<<< LEFT`), − → 오른쪽(`RIGHT >>>`) |
| 경고 중 \|오프셋 / 차선 폭\| < 14% | 경고 OFF |
| 차선이 없거나 차선 폭이 비정상 | 판단 보류 (오경보 방지) |
| 차량 중심 보정 중 (처음 2초) | 판단 보류 |

- 20%: 승용차 폭(~1.8m)과 차선 폭(~3.5m)을 생각하면 차량 중심이 차선 폭의 20% 정도 벗어날 때부터 바퀴가 차선에 가까워진다.
- 켜는 기준(20%)과 끄는 기준(14%)을 다르게 둬서(히스테리시스) 경계 근처에서 경고가 깜빡이지 않는다.
- 8프레임 연속 조건으로 허프 결과가 잠깐 튀는 것에는 반응하지 않는다.
- 경고 중에는 주행 영역이 빨간색으로 바뀌고 화면 상단에 `LANE DEPARTURE!` 배너가 뜬다.
- 기준값은 `DepartureWarning`의 `onRatio`, `offRatio`, `onFrames`에서 바꾼다.

**차선 이탈 경고 vs 차선 변경 감지:** 이탈 경고는 지금 차선 중앙에서 벗어나 있는지를 매 프레임 판단해 바로 알려 준다. 차선 변경 감지는 중앙에 머물다 크게 벗어나는 패턴이 끝난 뒤에 알려 준다.

## 차선 변경 감지

차선 중심의 오프셋 변화를 이용하는 간단한 감지 로직을 추가했다.

현재 방식은 차선 검출 결과가 안정적이라는 전제에 의존한다. 허프 변환 결과가 프레임마다 달라지거나 주변 차량, 그림자, 도로 곡률 등에 영향을 받으면 오프셋이 크게 변할 수 있다.

따라서 현재 차선 변경 감지는 실험 단계이며, 실제 차선 변경을 안정적으로 판별하는 기능으로 사용하기에는 한계가 있다.

향후 개선 방향:
- 차선 후보 픽셀 및 색상 정보 활용
- Bird's Eye View를 이용한 원근 변환
- 곡선 차선 추정을 위한 다항식 피팅
- 프레임 간 차선 위치 추적 및 안정화
- 차선 경계 통과 여부를 활용한 차선 변경 판단

## 빌드 (Windows)

OpenCV 설치 경로의 `lib` 폴더를 `OpenCV_DIR`로 지정해야 한다 (예: `.../opencv/build/install/lib`).

```bash
cmake -S . -B build -A x64 -DOpenCV_DIR=<opencv>/build/install/lib
cmake --build build --config Release
```

Visual Studio에서는 폴더를 열면 `CMakePresets.json`(+ 개인 경로용 `CMakeUserPresets.json`)으로 자동 구성된다. 실행 시 `opencv_world*.dll`이 있는 `<opencv>/build/install/bin`이 `PATH`에 있어야 한다.

## 실행

```bash
build/Release/lane_detection.exe <영상경로> [옵션]
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--preset` | `highway` | ROI 프리셋. `highway`(clip1~3), `city`(clip4, videoplayback) |
| `--width` | `960` | 처리 해상도 가로 (0 = 원본 1920) |
| `--blur` | `5` | Gaussian 커널 크기(홀수) |
| `--low` / `--high` | `30` / `90` | Canny 임계값 |
| `--auto` | 꺼짐 | 프레임 밝기 중앙값 기반 자동 임계값 |
| `--tune` | 꺼짐 | 트랙바로 blur/Canny/ROI 실시간 조절 |
| `--out` | 없음 | 결과 화면을 mp4로 저장 (데모 영상). **`--out=demo.mp4` 처럼 `=` 필수** |
| `--car-x` | 자동 | 차량 중심 x 비율(0~1). 생략하면 처음 2초 동안 자동 보정 |
| `--no-feature` | 꺼짐 | 차선 특징 영상(Top-hat) 끄고 흑백 영상에 바로 Canny (전/후 비교용) |
| `--no-blue` / `--no-yellow` | 꺼짐 | 파란 / 노란 차선 채널 끄기 (전/후 비교용) |
| `--debug` | 꺼짐 | 디버그 화면(결과+ROI / ROI 엣지+허프 선분)으로 시작. `--out`과 같이 쓰면 디버그 화면을 저장 |
| `--no-display` | 꺼짐 | 창 없이 실행 (속도 측정용) |
| `--max-frames` | `0` | 앞부분만 처리 |

키: `q`/`ESC` 종료, `Space` 일시정지, `d` 결과 ↔ 디버그 화면 전환, `s` 현재 장면 저장(`snap_프레임번호_raw/_result/_debug.png`, 실행한 폴더에 생성).

**시내 영상(clip4, videoplayback 등)은 반드시 `--preset=city`.** 기본값(highway)은 ROI 아래쪽이 화면 90%까지 내려가서 시내 영상에서는 보닛 테두리가 ROI에 들어가 차선으로 잡힌다.

옵션 값은 OpenCV `CommandLineParser` 규칙상 `--preset=city`, `--out=demo.mp4` 처럼 `=`로 붙여 쓴다.

```bash
# 데모 영상 녹화 (창 없이)
build/Release/lane_detection.exe clip1.mp4 --no-display --out=demo_clip1.mp4
```

종료 시 프레임당 처리 시간(전처리 / 전체 = 전처리~이탈 판정)과 FPS가 출력된다. 화면의 FPS도 같은 구간(표시·저장 제외)으로 계산한다.

## 차선 특징 영상 (Top-hat + 색 채널)

흑백 영상에 바로 Canny를 하면 **밝기가 바뀌는 곳이 전부** 엣지가 된다. 실제 영상에서 다음이 차선보다 먼저 잡혔다.

- 노면 이음매·타이어 자국 (노면보다 **어두운** 줄)
- 그림자 경계, 갓길 경계 (밝기 **계단**)
- 파란 차선 (흑백으로는 노면과 밝기가 같아 **아예 안 잡힘**)

차선 페인트는 항상 **주변 노면보다 밝거나(흰색·노란색) 파란, 가는 띠**다. 그래서 Canny 입력을 흑백 영상 대신 아래 "차선 특징 영상"으로 바꿨다.

1. **흑백 Top-hat**: `원본 − 열림(원본)`을 가로 커널(프레임 가로의 3.5%, 960px 기준 33px)로 한다. 커널보다 가는 밝은 띠만 남고, 어두운 줄·넓은 그림자·밝기 계단은 0이 된다. 2배 증폭.
2. **파란색 채널** `B − R`: 실제 영상 픽셀 측정 결과, 흑백으로는 파란 차선 88 / 노면 86으로 구분이 안 되지만 색으로는 차이가 크다.

   | | 파란 차선 B − R | 노면 B − R |
   |---|---|---|
   | 낮 (2015-10-28 14:50) | +18 ~ +25 | −32 (노면이 약간 붉은 회색) |
   | 해질녘 (17:20) | +26 ~ +32 | 0 ~ +3 |

   이 채널에도 같은 Top-hat을 해서(푸른 그림자처럼 넓은 영역 제거) 4배 증폭한다.
3. **노란색 채널** `min(R, G) − B`: 색이 바랜 노란 중앙선 강조. 회색 가드레일·노면은 0에 가깝다. Top-hat 후 3배 증폭.
4. 세 영상의 픽셀별 max → GaussianBlur(5) 이후의 Canny(30/90) → ROI 마스크.

하늘도 파랗지만 ROI 밖이라 제거된다. 추가 비용은 프레임당 약 1~2 ms. `--no-feature`, `--no-blue`, `--no-yellow`로 끄고 비교할 수 있다(보고서 전/후 캡처용).

## 파라미터 선정 근거

- **처리 해상도 960×540** : 원본 1080p 대비 픽셀 4배 감소. 전처리는 프레임당 약 2 ms (clip1~4, videoplayback에서 1.7~2.0 ms) 로 실시간 여유가 크다.
- **Grayscale + Gaussian 5×5, σ 자동** : 블러 없음/3/5/7/9를 Canny 30/90으로 비교했다 (ROI 내 엣지 픽셀 수).

  | 커널 | 없음 | 3 | 5 | 7 | 9 |
  |---|---|---|---|---|---|
  | clip1 | 2768 | 2412 | 1704 | 1213 | 1142 |
  | clip3 | 1841 | 1713 | 1514 | 1461 | 1235 |
  | clip4 | 6163 | 4819 | 3709 | 3030 | 2766 |

  3→5에서 잡음성 엣지가 크게 줄고, 7 이상에서는 clip1의 먼 곳 가는 차선과 clip4의 일부 차선이 짧아지거나 사라졌다. 정답 데이터가 없어 육안 비교이며, 5를 균형점으로 선택했다.
- **Canny 30/90 (1:3)** : 5개 클립의 같은 프레임에서 50/150, 30/90, 20/60, 자동(중앙값)을 비교. 50/150은 어두운 clip3에서 차선을 놓치고, 20/60은 가드레일·차량 엣지가 과다했다.
- **ROI는 Canny 이후에 적용** : 블러 영상에 마스크를 먼저 씌우면 ROI 경계선이 강한 엣지로 잡힌다.
- **ROI 프리셋** : 카메라 장착 높이가 클립마다 달라 두 가지로 나눴다 (비율 기반이라 해상도와 무관).

  | | topY | bottomY | top x | bottom x |
  |---|---|---|---|---|
  | highway | 0.60 | 0.90 | 0.42 ~ 0.58 | 0.03 ~ 0.97 |
  | city | 0.52 | 0.75 | 0.36 ~ 0.64 | 0.00 ~ 1.00 |

  `bottomY`는 보닛/대시보드가 시작되는 높이, `topY`는 소실점 약간 아래다. 새 영상에서는 `--tune`으로 맞춘 뒤 `applyRoiPreset()`에 값을 추가하면 된다.

## 알려진 한계

- ROI는 고정 사다리꼴이다. 차선 변경 중에는 옆 차선이 ROI 밖으로 나갈 수 있다.
- city 영상은 가드레일/횡단보도/차량 엣지가 ROI 안에 남는다. 허프 단계에서 기울기 필터링이 필요하다.
-  허프 변환은 직선 선분을 검출하므로 곡선 도로에서는 대표 차선 추정이 불안정해질 수 있다.
- 가드레일, 횡단보도, 차량, 그림자 등 차선이 아닌 엣지가 검출 결과에 섞일 수 있다.
- 현재 좌우 차선 분류는 기울기와 화면 중앙 기준으로 이루어져 복잡한 도로 환경에서 오검출이 발생할 수 있다.
- 오프셋은 ROI 중앙을 기준으로 한 상대적인 값이며, 카메라 설치 위치나 ROI 설정에 영향을 받는다.
- 차선 변경 감지는 현재 실험 단계이며, 경계 통과 판정이 추가로 필요하다.
- 이탈 경고는 카메라가 차량 중앙에 있다고 가정한다. 카메라가 치우쳐 있으면 오프셋 기준점 보정이 필요하다.
